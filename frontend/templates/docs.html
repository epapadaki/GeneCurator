GeneCurator: Human-in-the-Loop Gene Selector

A guided reference to the analytical workflow, methods, and design rationale.

BiHELab · Department of Informatics · Ionian University
{# --- Abstract --- #}

Abstract

GeneCurator is a web-based analytical framework for gene panel selection from differential expression data. The tool combines algorithmic feature ranking with structured expert oversight, addressing a well-documented limitation of purely automated ranking approaches: statistical significance does not, by itself, ensure biological interpretability. The application implements a four-step wizard workflow — data input, algorithmic ranking, expert curation, and downstream annotation — augmented by an optional large-language-model curation assistant and a ligand–receptor annotation module. This document describes the workflow, methods, and design rationale in detail.

{# --- 1. Background --- #}

§1 Background and motivation

Feature selection in transcriptomic studies is typically framed as a purely statistical problem: rank genes by a differential expression measure, apply a significance threshold or an importance criterion, and retain the top candidates for downstream analysis. This framing has clear advantages — reproducibility, computational efficiency, and transparent decision rules — but it collapses biological context into a single number. Consequently, automated rankings frequently promote genes with strong statistical signal but limited disease relevance: pseudogenes and non-coding RNAs are difficult to interpret, immunoglobulin variable regions reflect infiltrating lymphocytes rather than tumor-intrinsic biology, and adipocyte markers may reflect tissue composition rather than the process under study.

Manual curation by a domain expert can address these limitations by incorporating literature evidence, tissue specificity, and clinical actionability into panel design. In practice, however, purely manual curation is slow, difficult to reproduce, and prone to reviewer-specific bias. The two extremes therefore represent complementary rather than substitutable approaches. GeneCurator was designed to bridge them: the tool preserves the reproducibility of algorithmic ranking while exposing each ranking to structured, per-gene human oversight.

The design draws on a broader literature concerning human-in-the-loop machine learning, in which model outputs serve as structured hypotheses for human review rather than final decisions. In the biomedical context, this pattern has been described in the interpretation of imaging, variant classification, and pathway analysis. Applied here, the pattern yields a transcript-selection workflow in which the algorithm proposes, the expert disposes, and every decision is auditable.

{# --- 2. Workflow --- #}

§2 Analytical workflow

The application implements a four-step wizard in which each step exposes the outputs of the previous one and prepares the inputs for the next. Figure 1 summarises the pipeline.

2.1 Data input

The user provides an expression matrix in delimited text format (CSV, TSV, or whitespace-separated .txt), together with a sample metadata table. In the expression matrix the rows are samples and the columns are genes, with the first column holding the sample identifier. The metadata table has one row per sample and provides a sample identifier column and a group column, for example tumour or normal. The delimiter and encoding are auto-detected, the sample identifiers are matched between the two files, and the two groups to compare are read from the group column. From these inputs the application computes the per-gene differential statistics between the groups, which supply the p-value and the log-2 fold change used by the threshold method and by the plots. A synthetic sample-level example and a real TCGA-BRCA expression matrix are bundled with the application to allow immediate evaluation.

2.2 Feature selection

Six algorithms are available. The choice depends on the structure of the input signal and the analyst's downstream intent. Each algorithm produces a ranked list of genes and an importance score. The ranking is capped at a user-specified panel size (default: 50 genes) to keep the output tractable for expert review.

Algorithm-specific details are given in §3.1.

2.3 Expert curation

The curation stage presents the ranked candidate list alongside a gene inspector that surfaces functional annotation, disease association, and expression context for any selected gene. The reviewer may exclude candidates from the panel (typically because they are non-specific, redundant, or functionally uncertain) and may add genes that are present in the dataset but were not proposed by the algorithm (typically canonical biomarkers or clinically actionable targets). Every inclusion and exclusion is recorded and exported alongside the final panel.

An optional LLM curation assistant (§3.2) may be invoked at any point during curation. Its role is advisory: it produces structured suggestions with per-gene rationales, which the reviewer accepts or rejects individually.

2.4 Downstream analysis

The curated panel is passed to a suite of interpretive modules organised as tabs. Discovery summary provides a volcano plot of the full dataset overlaid with algorithm picks and expert-curated selections. The protein–protein interaction (PPI) tab constructs a subnetwork from STRING using the curated panel as seed nodes. Enrichment analysis (§3.4) tests the panel against fifteen reference libraries spanning pathways, ontology, diseases, cell types, and drug signatures. The ligand–receptor annotation tab (§3.3) flags panel members that appear in a curated LR database. The Log-2FC profile provides a compact ranked view of expression magnitude across the panel.

{# --- 3. Methods --- #}

§3 Methods

3.1 Feature-selection algorithms

Six algorithms are implemented. Together they span the standard feature-selection archetypes used in transcriptomic studies: threshold-based selection, ensemble tree importance, regularised regression, and kernel-based selection. A method guide in the interface describes, in plain language, the assumptions of each method and the data conditions under which it fits, so that the user can match the method to the size and the signal of the dataset. The choice of method remains with the user.

Algorithm Type Principle
Traditional DEG (Volcano) Threshold Genes above a user-defined significance and effect-size cut-off, ranked by −log10(p).
Random Forest Ensemble Impurity-based importance from a bootstrap-averaged decision tree ensemble.
Gradient Boosting Ensemble Sequentially fitted boosted trees; feature importance from cumulative split gain.
LASSO (L1) Regularised regression L1-regularised logistic regression on the group contrast; non-zero coefficients define the panel.
Elastic Net (L1+L2) Regularised regression Elastic-net-regularised logistic regression; combined L1 and L2 penalties for correlated-feature stability.
SVM + RFE Kernel Linear support-vector classifier with recursive feature elimination; genes ranked by the effect of their removal on group separation.

Implementations use scikit-learn 1.4 for Random Forest, LASSO, Elastic Net, and the support-vector classifier, and XGBoost 2.0 for Gradient Boosting. Traditional DEG selection is implemented natively. The five supervised methods treat gene selection as a classification problem in which the samples are the observations and the genes are the features, and they rank or select genes by their contribution to separating the two sample groups. Random Forest and Gradient Boosting use impurity-based feature importance, LASSO and Elastic Net use the non-zero coefficients of a regularised logistic regression, and the support-vector method uses recursive feature elimination. The Traditional DEG method instead applies fixed thresholds to the computed p-value and log-2 fold change. The output is capped at the user's requested panel size, which the user may modify at Step 2.

3.2 LLM curation assistant

An optional curation assistant leverages Google Gemini 2.5 Flash via the Anthropic-style tool-use pattern. Given the current panel, the top-ranked genes in the dataset, and a user-declared biological context, the assistant returns a structured JSON payload with three fields: a context summary, a set of removal suggestions (with per-gene rationale), and a set of addition suggestions constrained to canonical markers already present in the dataset.

Two prompt templates are used: the first treats the user-declared context as ground truth, and the second is triggered when no context is provided. In the latter case, the assistant is instructed to infer the tissue type from the expression pattern and to flag the inference as uncertain in its context summary. Suggestions are shown in the interface as accept/reject cards; no suggestion is applied without explicit user confirmation. Temperature is set to 0.2 to encourage consistent, conservative output.

The assistant is advisory and does not replace expert review. Its role in the workflow is to accelerate first-pass curation while preserving the reviewer as the final decision authority.

3.3 Ligand–receptor annotation

The ligand–receptor annotation module annotates the curated panel against a curated database of known human ligand–receptor pairs. The database used is CellTalkDB (Shao et al., 2020), accessed via the LewisLab UCSD compendium. CellTalkDB contains 3,398 human LR pairs derived from manual curation of primary literature, with each pair linked to a PubMed identifier.

For a given curated panel, the module returns four categories of annotation:

  1. Panel members with a known ligand or receptor role;
  2. Complete LR pairs entirely contained within the panel;
  3. Partial pairs in which a receptor is in the panel and its known ligand is present in the dataset but excluded;
  4. Partial pairs in which a ligand is in the panel and its known receptor is present in the dataset but excluded.

Each partial-pair entry exposes an inline action that adds the cognate partner to the panel and re-triggers the annotation. This design extends the human-in-the-loop paradigm to cell-communication considerations.

Note. This module provides annotation only. It does not infer cell-cell communication events, which require single-cell-resolution data. It answers the narrower question of which panel members are catalogued as signalling molecules and which known pairs are jointly represented.

3.4 Enrichment analysis

Enrichment analysis is performed via the Enrichr web service (Chen et al., 2013; Kuleshov et al., 2016). Fifteen libraries are queried in parallel and organised across five conceptual tabs.

Tab Libraries
Pathways KEGG 2026, Reactome 2024, WikiPathways 2024, BioPlanet, MSigDB Hallmark
Ontology GO Biological Process 2026, GO Molecular Function 2026, GO Cellular Component 2026
Diseases DisGeNET, OMIM Disease, Rare Diseases GeneRIF
Cell types PanglaoDB Augmented 2021, Human Gene Atlas
Drugs DSigDB, Drug Perturbations from GEO (up / down)

Each library returns terms ranked by Fisher's exact-test p-value with Benjamini–Hochberg-adjusted q-values (FDR). Terms with FDR below 0.25 are highlighted; terms with FDR below 0.05 are emphasised as high-confidence associations. KEGG pathways include a rendered pathway diagram with panel genes highlighted, retrieved from the KEGG REST API.

3.5 Protein–protein interactions

The PPI network is constructed by querying the STRING v12 database for interactions among the curated panel members. The default confidence threshold is 0.4 (medium), which corresponds to STRING's standard threshold for interactome exploration. Edges combine evidence from experimental, database, coexpression, and text-mining channels. The resulting subgraph is rendered with a spring-embedded layout in the browser.

3.6 Per-gene evidence

For any selected gene the interface displays functional annotation retrieved from UniProt (function, disease involvement, subcellular location) and a link to the corresponding UniProt entry. This evidence panel appears alongside the ranked candidate list at Step 3 and is the primary source of biological context during expert curation.

{# --- 4. Data requirements --- #}

§4 Data requirements

The tool accepts an expression matrix from any standard bulk RNA-seq or microarray pipeline, together with a sample metadata table that assigns each sample to a group. Values should be on a normalised, roughly log-scale (for example log-2 counts per million); raw counts are flagged so that the user can apply a log transform. The required structure of the two files is described in Table 3.

File Content Notes
Expression matrix Samples in rows, genes in columns; first column is the sample identifier Gene columns use HGNC symbols (preferred) for direct annotation lookup; the remaining values are numeric expression levels.
Sample metadata One row per sample: a sample identifier column and a group column The group column defines the contrast, for example tumour versus normal; at least two samples per group are required.

From these inputs the application computes the per-gene p-value and log-2 fold change between the two groups, so a pre-computed differential expression table is not required. The tool is species-agnostic in its statistical stages but the enrichment libraries, PPI database, and LR annotation are all human-specific. Non-human inputs will pass through the pipeline but will typically produce empty or misleading downstream annotations.
